shipped:

1. **Every lane carries the shared communication surface.** The register gives
   every role a `communicationPaths` list (the queue, the status board and the
   proof folder), the generated agent files allow exactly those paths next to
   the work scope, and the role gate refuses a register without that list. This
   landed on `main` in commit 2e9becb9 and is the register's one source; the
   scope and the communication surface are read from it, never written twice.
2. **The scope rule is machine-checked.** `scripts/verify/role-scope.ts` sits
   beside `scripts/verify/scope-check.ts`, reads the one role register, and
   refuses a changed path outside the named role's `scopePaths` except that
   role's own `communicationPaths`. It is registered as `npm run scope:role`.
3. **The gate can fail.** The verifier reads the changed paths from the diff
   itself (`--base`/`--head`) and refuses a caller-supplied path list, because
   a caller that lists paths itself could list only the paths it may touch.
   The role gate runs the command as a child process in a temporary repository
   and asserts the non-zero exit and the refused path in its output, so the
   proof is the command and not only the exported function.
4. **Every lane session runs the gate before it merges.** The generated
   `.opencode/agents/*.md` and `.claude/agents/*.md` files carry the command
   the verifier accepts, with that role's own id and the base ref the lane's
   pull request targets
   (`npm run scope:role -- <role-id> --base <the base ref your pull request targets> --head HEAD`),
   and the role gate proves the line is in both harnesses. The dispatcher lane
   carries the same command in the lane prompt it hands each worker, with
   `origin/main` as the base, which is right for a lane branched from main.
