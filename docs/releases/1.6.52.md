# WHAT REACHED THE SURFACE

One click now pairs the browser this dashboard is open in. The "Pasangkan browser ini" button mints a one-time code through the same RPC as the manual flow, then hands it straight to the extension as a bearer token (`chrome.runtime.sendMessage` to the pinned extension id); the code never appears, never touches a clipboard, and the extension redeems it exactly as it redeems a code pasted from the popup. If this browser's extension build does not know the `pair` message yet, the page answers with the manual flow's message instead of an error. (#318)

Chrome for Testing joins the install (#315): the installer detects it through a one-level wildcard over the Playwright cache (`chromium-<rev>/chrome-win64/chrome.exe`) and the Google folder, registers it with the same `HKCU` update trigger key, lays down a verified backup, and uninstalls it like the other three browsers.

The local MCP surface speaks agent-native (#312): nine tools renamed to the names agents already reach for (`append_text`, `read_caret_line`, `query_page`, `snapshot_page`, `scan_page`, `run_steps`, `use_browser`, `wait_for_text`, `wait_for_stable`); `list_devices` is folded into `browser_status` (one answer carries devices, plan, allowances and the pin); `document_build` is folded into `document_write`; and `wait_for_url` is new. Surface count: 56 tools.

`use_browser` (formerly `switch_device`) pins tab-less commands (`open_url` is the one that matters) to one paired browser, by slot number, by name, or `any` to follow every awake browser again (#310). A sleeping pin is refused loudly with the awake list, never silently typed into the wrong signed-in profile.

The hosted MCP function is gone from production (#308, recorded in #309). OpenCode and every other caller now talk to the local driver (`opera-agent-mcp`) and the pairing bridge only.

Search and open got honest (#313, #314): `open_url` reads the opened tab instead of the background window, and `search_bing` waits for the page to carry text before reading - a SERP that answers empty because it has not loaded yet is not a verdict. The HTTP doors re-probe a dead adopted bridge instead of staying dead (#311).

# WHAT CHANGED FOR CALLERS

- Nine tools have new names. Callers on the old names get `tool not found`; the replacements are one-to-one: `append` → `append_text`, `caret_line` → `read_caret_line`, `ask_page` → `query_page`, `ax_snapshot` → `snapshot_page`, `surface_profile` → `scan_page`, `browser_burst` → `run_steps`, `switch_device` → `use_browser`, `wait_for` → `wait_for_text`, `wait_still` → `wait_for_stable`.
- `list_devices` is gone; `browser_status` answers devices, plan, allowances and `preferredSlot` in one object. `document_build` is gone; `document_write` returns the plan alongside the file.
- The hosted function URL (`.../opera-agent-mcp` on Supabase) answers nothing anymore. A caller still registered there must re-register the local server: `opera-agent-mcp` over loopback (`OPERA_LOCAL_TRANSPORT=bridge` behind the paired extension, or a browser with remote debugging over CDP).
- The meter is local-only: `plan.firm`, 500/day session allowance, 5000/day account cap, counted where it is enforced.
- The extension and every clock read 1.6.52. `wait_for_url` replaces the wait no text-read and no still-wait could express.
- The one-click pair needs this build: an extension older than 1.6.52 does not know the `pair` message and the button falls back to the manual code flow by design.

# WHAT IT COSTS THE READER

Anyone holding an agent prompt that names `switch_device`, `list_devices` or the other eight old names rewrites nine lines, or the agent sees `tool not found`. Anyone still pointed at the Supabase function re-registers the local one; that is a one-time change with the same tool surface after the nine renames. The hosted road is closed, not degraded: there is exactly one road now, and it runs on the machine.
