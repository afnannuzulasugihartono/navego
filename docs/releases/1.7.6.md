# 1.7.6 - the rename ships end-to-end

- **Navego is the only name left on the wire, in the CLI, in the CRX, on the site, in the docs, and in the MCP registry.** Everywhere a name appears - packages, hosted function directories, schemas, CI, migrations - it is `navego`.
- **`navego doctor --json` emits one object**: `{ ready, port, deviceFile, cloudLogin, bridge: { ok, devices, linked, refusal, preferredSlot }, problems[], crxUrl }`, so MCP clients and scripts stop parsing prose.
- **MCP Registry publishes from CI** via `publish-mcp.yml`: npm OIDC trusted publishing plus GitHub OIDC for the registry, triggered by the same dispatch flow used for releases.
- **Rename across the tree**: `OPERA_*` env vars -> `NAVEGO_*`, hosted functions `opera-agent-*` -> `navego-*`, internal schemas `opera_agent_tx_candidate` -> `navego_tx_candidate` and `opera_agent_private` -> `navego_private` (live DB renamed via migration `20261118000000_rename_dark_schemas.sql`).
- **CRX manifest** stays `Navego v1.7.6`; the extension id, signing key, and wire contract are unchanged.
- **Docs** point npm users to `npx -y navego`; `navego doctor --json` and the MCP Registry publish are documented in the README and `llms.txt`.

The release tag for this build is `v1.7.6`.
