# WHAT REACHED THE SURFACE

The manual pairing door is gone from every surface that carried it. The popup no longer offers "Pairing" with a paste-the-code field; the dashboard no longer offers "Buat kode pairing" with a code box, a countdown and a copy button; the homepage and download page product demos no longer show a pairing code or its ten-minute clock; the options page and the download docs no longer teach the paste. One door remains, everywhere it is shown: **Pasangkan browser ini** - the dashboard mints a single-use code and delivers it straight to the extension in that browser; the person never sees the code, never types it, never copies it. (#327)

The dashboard's pairing section itself changed shape: `Pairing manual` is now `Pairing`, with the device name field and the one-click action as its only contents. The empty-devices state points at the same door. The landing demo screens now show the one-click panel and the paired state instead of the code panel.

A latent defect the change surfaced is fixed in the same breath: the `{error}` placeholder in the one-click failure message was never interpolated, so a failed pair printed its template literally; the message now renders through `fmt()`, and a browser that cannot receive a code (`no-extension`, `no-runtime`) answers with the plain no-extension copy instead of a raw failure string.

# WHAT CHANGED FOR CALLERS

- No tool moved; the surface stays 56 tools. The 36-method protocol did not move. Every clock reads 1.6.54.
- The extension popup's message contract with its worker is unchanged; the pairing action the popup used (`{ action: 'pair', code }` with `scope: 'navego-popup'`) is the same one the dashboard's one-click flow drives. No automation should be built against the manual flow again - it no longer exists.
- The dashboard's pairing surface is now the one-click action; `?pair=1` with an active session fires it once per load and scrubs the parameter (since 1.6.53, unchanged here).

# WHAT IT COSTS THE READER

An update still has to reach the machine. Chrome and Edge force-install from the policy entries already on this machine; a load-unpacked copy does not self-update - the person reloads the folder (`C:\Users\ASUS\AppData\Local\Navego\brave\unpacked`) at `brave://extensions`, one click, or restart that browser.

A reader who had bookmarked the paste-the-code panel is out of luck by design: the panel is gone, and the replacement is one click on the same dashboard, not a new ceremony.
