# WHAT REACHED THE SURFACE

The popup grew one row, and it is the first one: **Pasangkan browser ini**. One click there opens the dashboard with the one-click pair already running - the code is minted and handed to the extension in this browser, never typed, never pasted, never seen. (#324)

The dashboard learned that handoff: open it with `?pair=1` and, with an active session, it fires the same one-click action the orange button fires, once per load, then scrubs the parameter from the address bar - no accidental re-mint on refresh, ever. No session: the page behaves exactly as before and the button stays put. (#324)

The first run now answers the only question a fresh install gets: **Tinggal satu klik.** On `chrome.runtime.onInstalled` with `reason: "install"` alone, the extension opens its own first-run page - logo, one status line ("Terpasang di browser ini"), one headline, one green CTA to the dashboard's one-click flow. Updates never open it; reloads never open it. (#325)

# WHAT CHANGED FOR CALLERS

- Nothing in the protocol moved; the 36 primitives are untouched and `wait_for_url` stays the newest primitive. The surface is 56 tools, unchanged.
- The version is `1.6.53` everywhere - extension, npm package, update manifest, store listing, MCP server `SERVER_VERSION`, every test pin.
- `chrome.runtime.onInstalled` now exists for one more reason than before: the first-run page, and only for `reason === 'install'`. Callers driving the worker see nothing new.
- The onboarding page carries no scripts and needs no new permissions; it links one anchor to the dashboard.

# WHAT IT COSTS THE READER

An update has to reach the machine that runs the reader's browser. Chrome and Edge force-install from the policy entries (they reinstalled themselves through every release of the month without a click). A load-unpacked copy does not self-update: the person takes the build into the folder it was loaded from and presses reload - the same one manual step the reader already knows from every earlier release.

The first-run page fires once, on a fresh install, in the browser being installed. It never fires on update.
