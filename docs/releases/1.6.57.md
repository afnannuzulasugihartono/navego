# WHAT REACHED THE SURFACE

Every full-height surface the extension owns now renders from ONE frame file (`extension/page-frame.css`): the same canvas, the same column, the same mark above a wide island card, the same type roles. The first-run page and the automatic-update page are twins by construction - a brand row, one headline, one sentence, one status line, one accent button, documentation to the right of a quiet foot line - and the card shows the product itself (a live render of the popup) instead of describing it. Both pages lost their local copies of the frame; both carry exactly one claim. The popup was tightened to the same discipline: the folder invitation is a quiet row, the chip toggle is a real switch, the language no longer bleeds Indonesian into an English panel, and the only fill in the panel is the action that still needs doing. The first-run page's button no longer opens a second tab: one press navigates the same tab into the dashboard's one-click pair flow.

# WHAT CHANGED FOR CALLERS

- No tool moved; the surface stays 56 tools. Every clock reads 1.6.57.
- `extension/onboarding.css` is gone; the frame lives in `page-frame.css` and is linked by both pages. The first-run page's CTA navigates same-tab; the popup's chip row is a real switch (`role="switch"` with a drawn track and knob), its state persists as before (`oa_chip_enabled`).
- The update page auto-applies right after the folder pick; its action is one button that branches (allow the folder once, or write the build over it). The update manifest, the store listing, the MCP server `SERVER_VERSION`, the root and local `package.json` files - every clock 1.6.57.

# WHAT IT COSTS THE READER

Nothing new: the one-time folder pick, once, and then updates install themselves.
