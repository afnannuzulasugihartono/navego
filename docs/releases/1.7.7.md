# WHAT REACHED THE SURFACE

- **Nothing brings a window to the foreground anymore.** `browser_focus_window` is deleted end-to-end: the schema, the dispatch case, the driver method, the primitive, the bin wrapper, the guide recipe and its side-effects entry are all gone. `browser_status` still answers which browser is in front, and the session-level guard in `local/focus-guard.ts` restores a minimized session window only when the page cannot hear input — it is not agent-callable. The drive runs in the background.
- **Screenshot answers in the background.** When the compositor has no frame for the tab (locked screen, minimized or hidden window), `browser_screenshot` retries with `captureBeyondViewport` clipped to the current viewport top, and the answer names the road: `compositor` or `beyondviewport`.
- **`browser_read_page` is bounded.** `maxChars` (clamped to 100000, `originalChars`/`truncatedChars` reported) caps the text it returns, and `selector` reads only the `innerText` of the first matching subtree — settled twice, and a match it cannot make refuses with the reason instead of streaming the whole page.
- **Two merges, 45 → 42 tools.** `artifact_build_report` absorbs `artifact_build_workbook` (`format: word | xlsx`, the identical parameters stayed one shape), and `browser_find_element` absorbs `browser_find_text` as `mode: element | text`. The guide workbook recipe now names the one tool instead of a name that no longer exists.
- **Every description is two sentences.** The catalog's words fell from 3,877 to 1,323 (-66%). The pinned safety facts stay verbatim: never-stale handle, canvas fullPage stops at the viewport, atEnd wording (`found:false`, `read()`, `table cell`), the scroll's measurement (`which scroll container moved`, `travelPx`, `no answer at all`), and `front` in the status description.
- **Guide names the two roads to proof.** `Prove it worked` now distinguishes a text claim, which `browser_read_page` settles, from a visual claim, which only a picture settles; when the tool says it worked and the page did not change, suspect the picture first.
- **`browser_intercept_picker` restores by itself.** Enabling intercepts arms a 2-minute restore (fresh timer per enable), disable clears it, and the answer names `interceptedSince` and `elapsedMs`. The silent "later Upload clicks are swallowed" failure cannot survive an abandoned drive.
- **The tool log comes with the package.** `navego failures` prints what broke on this machine (counts by tool and code, the recent failures, every note), and `navego feedback <tool> <note>` lets the calling agent leave the improvement where the maintainer will find it. Both ride a local file, `$OPERA_AGENT_HOME/tool-failures.jsonl`, and nothing leaves the machine.

# WHAT CHANGED FOR CALLERS

- **44 → 42 tools.** If a caller names `browser_focus_window`, `browser_find_text` or `artifact_build_workbook`, it gets "tool not found". Replace: the foreground no longer exists as an action; `browser_find_element` with `mode: "text"` is the find; `artifact_build_report` with `format: "xlsx"` is the workbook.
- **Describe-your-operation**: `navego failures` can now answer "which tools failed on this machine and why" without a server round trip.
- Agents that relied on the whole page text stream should pass `maxChars` and receive exactly the cap, with both counts.
- Nothing in the wire contract, protocol, extension, or the proof harness moves.

# WHAT IT COSTS THE READER

Nothing is gated longer or higher: type-debt 0, runtime safety 304, the suite unchanged in scope. Descriptions are shorter, so the catalog is cheaper in every client that loads it.

# EVIDENCE, NOT GUESSES
