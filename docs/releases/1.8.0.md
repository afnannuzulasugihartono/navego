# WHAT REACHED THE SURFACE

- **Every tool call is validated against the schema the client reads.** The runtime check and the catalog cannot drift apart, because both read the same `inputSchema`.
- **The boundaries validate their input before typed code sees it.** The migration script validates the shape of the Supabase token and project reference; the site validates the shape of an auth refresh answer; every edge function reads `SUPABASE_URL` and, where it needs it, `SUPABASE_SERVICE_ROLE_KEY` through one validator instead of reading them as empty strings.
- **The migration history is proven against a real database.** CI applies all 131 migrations to a disposable Postgres on the Supabase baseline image under `ON_ERROR_STOP` and then asserts the shapes that matter: the command lifecycle check and the row-level security on the billing tables. Three files could not have run from the repository as committed - one closed a call it never closed, one began with a byte-order mark, and one moved a function twice - and all three are fixed.
- **The branch is protected.** `main` requires the CI checks with strict verification, refuses force pushes and deletions, and asks for an approving review with code-owner sign-off on the gatekeeper paths.
- **Nothing fails silently any more.** Every failure the product catches and ignores is listed with the reason it may be ignored, and the gate refuses a failure that is not listed and a line that names a failure the tree no longer has. The list can only shrink.
- **The predecessor product's names are gone from the live surfaces.** The tool log lives at `~/.navego/tool-failures.jsonl` under `NAVEGO_AGENT_HOME`, the static token is read from `NAVEGO_MCP_TOKEN`, and the two keepwarm jobs that pointed at the deleted `opera-agent-mcp` and the renamed `opera-agent-bridge` are unscheduled, rescheduled and pointed at `navego-bridge`.
- **The secrets and the logs are hardened.** A credential file refuses an account without a password, a failure log redacts before it writes, and the log keeps its permissions on POSIX and on Windows.

# WHAT CHANGED FOR CALLERS

- **`NAVEGO_AGENT_HOME` replaces `OPERA_AGENT_HOME`,** and the tool log moves with it to `~/.navego`. A machine that set the old variable keeps its log under the old path until it points the variable at the new home.
- **`NAVEGO_MCP_TOKEN` is the name of the static token.** The old `OPERA_AGENT_MCP_TOKEN` was never read by the code; the documentation now names the variable that is.
- **Nothing in the tool contract moved.** The 40 tools, their schemas and their answers are the same.
