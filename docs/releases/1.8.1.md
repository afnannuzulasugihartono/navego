# WHAT REACHED THE SURFACE

- **Every hosted edge function reads its JSON body through one shared rule.** A body must be a plain object: a body that is malformed JSON, `null`, an array or a primitive is refused with that function's own 400 before typed action code sees it. The gateway answers `INVALID_JSON` and status 400 for a JSON `null` or array, as `docs/api.md` promises; the bridge, listen, runner, OCR and feedback edges keep their own envelopes, and billing still normalises a non-object body to the empty object so its documented "unknown action" refusal is unchanged.
- **Every cap a tool description advertises is declared in the schema the client reads.** The runtime validator now enforces what the prose promised: `browser_read_page.maxChars` at most 100000, `browser_search_web.timeoutMs` at most 30000, `browser_find_element.limit` at most 500, `browser_run_steps.timeoutMs` at most 12000, and `browser_wait_until.timeoutMs` at most 60000. A call past a cap is refused by name instead of being quietly clamped.
- **A paired device leaves the predecessor's bridge deployment.** A device paired before the bridge function was renamed still stored the predecessor's bridge URL, so it kept talking to a deployment whose bundled plan table predated the USD sale. The extension now rewrites that stored URL to the current slug and persists it, once, so the device leaves the old deployment and stays on the deployed one. The Options page and the worker read the same rule.
- **The daily quota comes from the account, not from the build's table.** The gate takes the quota from the account profile it already reads, and the bundled plan table is only the fallback for a profile that carries no quota. A build whose table predates the current sale can no longer charge an account a quota it never bought - the failure that refused a `plan.usd-17` customer with "today's quota of 200 commands".
- **The repository says what it holds.** The architecture map names 131 migrations and ten edge functions, the handoff names the six CI gates that run and that `main` requires, the security policy names 1.8.x as the supported line, and three documents that still claimed 45 tools now say 40.
- **The MCP Registry manifest moves with every release.** It advertised 1.7.6 while the package was 1.8.0; the version bump now carries it, so the registry cannot drift from the package again.
- **The client snippets carry the shape each client reads.** The agent-friendly guide gave OpenCode the generic `mcpServers` shape, which OpenCode does not read; it now gives the `mcp.servers` shape with `"type": "local"`, the install guide names the local mode that drives the everyday browser, and the repository's own `opencode.json` registers Navego.

# WHAT CHANGED FOR CALLERS

- **A malformed or non-object hosted body is now a 400 with a named reason.** The bodies that used to reach typed code (and, for the gateway, answer a 502) are refused at the door.
- **A call past an advertised cap is refused by name.** The tool names, their schemas and their answers are the same 40; what changed is that the caps in the descriptions are now the caps the server enforces.
- **The tool surface is unchanged.** 40 tools, same names, same schemas, same answers.
- **Nothing new has to be configured.** The bridge URL migration runs on the device; no environment variable and no command changed.

# WHAT IT COSTS THE READER

Nothing to read and nothing to set. A paired device that was stranded on the predecessor's bridge moves itself onto the deployed one the next time the worker starts.
