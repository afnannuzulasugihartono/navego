# @title: 2.0.0 - the product is Opera: one name across the tree, the registry, the environment and the wire, with the 1.x names still read.
# @state: the rename is in the tree; publishing, the trusted publisher, the edge deploy and the legacy endpoint window are the owner's acts.
# @dependencies: 1.7.7 base. Publishing is `publish-npm.yml`; the edge functions are `deploy-functions.yml`; the CRX is `publish-crx.yml`.

# WHAT REACHED THE SURFACE

- **The name is Opera everywhere a human reads it.** The manifest, the popup, the update page, the site, the store manifest, the MCP server, the edge functions, the tool catalog, the docs and the tests all answer Opera. The product version moves to 2.0.0 because the name is a breaking change, not a cosmetic one.
- **The npm package is `opera-agent`, the command is `opera`.** The registry name `opera` belongs to a third party (a 0.0.10 package), so the package carries the product name with a suffix and the command carries the bare name. `navego` stays installed as an alias of the same file for one major, so an existing script does not break on the day of the upgrade.
- **The environment moved to `OPERA_*`.** Every configuration variable is read under its new name. A `NAVEGO_*` variable is still read: the first process start copies it into the canonical name when the canonical name is unset, so an existing `.env` keeps working without an edit.
- **The device token header moved to `x-opera-token`.** The hosted functions read the 1.x `x-navego-token` header as a fallback, so a client that has not been upgraded yet is still answered; the canonical header is read first when both are sent.
- **The home moved to `~/.opera`.** A device paired before the rename is still found at `~/.navego/device.json`, and the bridge token still lives at `~/.navego/bridge-token`. A new pairing is written to the new home.
- **The applied migration history was not rewritten.** The 130 migration files keep their bytes; only the file label carries the new name, because the version prefix is the identity and the ledger records the version. Two of those files could never have run as committed - one had an unclosed call, one carried a byte-order mark - and both are fixed in this release.
- **The enterprise pass rode along.** Runtime validation of every tool call against the schema the client reads, credential files that refuse an empty password, failure logs that redact secrets and keep their permissions on POSIX and Windows, an OAuth callback that no longer stops a login in flight, a single-flight refresh-token race fix, a PostgreSQL lane that applies every migration under `ON_ERROR_STOP` and asserts the result, branch protection on `main`, a dispatcher split by domain, and environment and body validation on the hosted functions.

# WHAT CHANGED FOR CALLERS

- **`npx navego` keeps working.** The `navego` command is an alias of `opera`; new installs should use `opera`.
- **Configuration keys moved.** `NAVEGO_BRIDGE_PORT` is still read and `OPERA_BRIDGE_PORT` is the canonical name. A file with both is answered by the canonical one.
- **The token header moved.** A caller that sends `x-opera-token` is read first; `x-navego-token` is still accepted until 3.0.
- **The edge endpoints moved.** The functions are `opera-bridge`, `opera-billing`, `opera-auth`, `opera-gateway`, `opera-ocr`, `opera-listen`, `opera-runner`, `opera-update`, `opera-vm` and `opera-feedback`. The deployed `navego-*` functions must stay alive for one release: an installed 1.x extension polls `navego-update/update.xml` for its CRX, and that URL is baked into every installed copy.
- **Nothing in the tool contract moved.** The 40 tools, their schemas and their answers are the same; the release renames the product around them.

# WHAT THE OWNER HAS TO DO

1. Publish `opera-agent` on npm and set its trusted publisher to this repository (the workflow that publishes it is `publish-npm.yml`).
2. Deploy the renamed edge functions (`deploy-functions.yml`, the `opera-*` list), and leave the deployed `navego-*` functions in place for one release.
3. Rename the Cloudflare Pages project and the GitHub repository when they are free to move; the tree keeps the current addresses, so the site and the repository links keep working until then.
4. Rotate the Cloudflare token to a read-only scope, which was left open by the security review and is not a code change.
