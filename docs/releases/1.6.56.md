# WHAT REACHED THE SURFACE

Two things the panel was lying about, fixed. The CTA said \`Pasangkan browser ini\` on a browser that is paired - it is now \`Browser ini terpasang\` / \`This browser is paired\`, green, a check instead of a bolt, and the press opens the dashboard where pairing lives. The update surface was three doors for one job (a zip download that walked the reader to \`chrome://extensions\`, an \`Update otomatis\` row, a \`Perbarui sekarang\` row); it is now ONE door that branches: folder never allowed -> \`Allow the folder once\`, which opens the update page holding the picker the popup cannot hold, and the page finishes the job itself once the pick happens (writes the build, restarts the worker); folder allowed and a newer build served -> \`Update to {v}\`, one press, no File Explorer; folder allowed and nothing new -> the door hides. The update page was rebuilt to the island shape in the same pass, and \`lib/status-icons.ts\` is deleted with its last consumer.

# WHAT CHANGED FOR CALLERS

- No tool moved; the surface stays 56 tools. Every clock reads 1.6.56.
- The popup's internal markup changed again (\`updateNowButton\`/\`autoUpdateButton\`/\`updateHint\` gone, \`updateDoorButton\` in); \`update.html\` now reloads the worker only after an applied build. \`lib/status-icons.ts\` is gone; the four dead i18n keys (\`update.available\`, \`update.download\`, \`update.now\`, \`reload.extension\`) are gone from both language tables.

# WHAT IT COSTS THE READER

The update page needs the File System Access API. Brave hides it behind \`brave://flags\` (\`file-system-access-api\`, Enabled, Relaunch); Chrome, Edge, Opera and Vivaldi carry it already. The 30-minute alarm applies an update only for a folder the reader allowed once; everyone else keeps the door.
