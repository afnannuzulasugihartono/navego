# WHAT REACHED THE SURFACE

The local MCP server's tool surface was cut from 56 to **40** tools and renamed end to end: every tool is `browser_` plus a `verb_noun` name (MCP tool names tolerate only `[a-zA-Z0-9_-]`, so the dot remains the wire namespace — `page.click`, `tabs.list` — and the Postgres names stay `snake_case`). `initialize` now also announces the server and what it drives: "Corbin drives the user's real, signed-in browser." The release work behind it: the public site was rebuilt as **Corbin** (Y2K retro, flat html prerendered from React Router v7, the raven mark), it is deployed to `navego.pages.dev`, and its claims read consistent — every page states 40 tools. Every version clock in this release reads **1.7.1** (extension manifest, protocol `SERVER_VERSION`, root and local `package.json`, the store listing, the update manifest, the site badge, every test pin, `gates.lock`).

Folded or deleted (gone is gone): `probe` (read measures the surface itself), `trace` and `caret` (the raw CDP read and the caret-line read are not MCP tools anymore), `inspect`, `grab` + `tap` (→ `browser_click` with `role` + `name` or a handle — the resolve and the centred click are one call now), `append` (→ `browser_type` with `atEnd: true`; ended-ness is measured, never assumed), `stream` (→ the `stream` step inside `browser_run`), and `scan` (→ `browser_find` with `role`, plus a `name` for the one row and its handle). `menus` + `menu` became one tool (`browser_menu action=list|walk`). `browser_wait` grew honest `until=url` and `until=stable` support instead of inferring. `browser_find` does exactly one thing per call.

# WHAT CHANGED FOR CALLERS

Every tool is renamed; the table is mechanical, the two structural folds are not:

- 56 (1.6.59) → 40 (this release). The old names map one-to-one onto `browser_` + the same job name (`status`→`browser_status`, `front`→`browser_front`, `dialog`→`browser_dialog`, `pin`→`browser_pin`, `tabs`→`browser_tabs`, `goto`→`browser_goto`, `close`→`browser_close`, `read`→`browser_read`, `search`→`browser_search`, `find`→`browser_find`, `click`→`browser_click`, `hover`→`browser_hover`, `press`→`browser_press`, `type`→`browser_type`, `scroll`→`browser_scroll`, `run`→`browser_run`, `wait`→`browser_wait`, `upload`→`browser_upload`, `drop`→`browser_drop`, `chooser`→`browser_chooser`, `download`→`browser_download`, `menu`/`menus`→`browser_menu`, `guide`→`browser_guide`, `shot`→`browser_screenshot`, `card`→`browser_card`, `delivered`→`browser_delivered`, `report`→`browser_report`, `sheet`→`browser_sheet`, `deck`→`browser_deck`, `doc`→`browser_doc`, `portal`→`browser_portal`, `login`→`browser_login`, `captcha`→`browser_captcha`, `pair`→`browser_pair`, `balance`→`browser_balance`, `quote`→`browser_quote`, `topup`→`browser_topup`, `reserve`→`browser_reserve`, `settle`→`browser_settle`, `refund`→`browser_refund`).
- `append` → `browser_type atEnd:true`.
- `grab`, `tap` → `browser_find` (role/name for the one row) or `browser_click role+name` (the centred click in the same call).
- Anything that was a CDP escape hatch and is not an MCP tool has no replacement.
- The guides (`browser_guide`), the docs (`docs/agent-call.md`, `local/README.md`) and the site now claim 40 tools everywhere; in-tree examples already use the new names. Any hardcoded script or harness config needs the `browser_` prefix — there is no bridge alias and none is coming.
- This is a breaking name change on the 1.x line; no deprecation alias ships.

# WHAT IT COSTS THE READER

Your scripts, prompts and harness configs must move to the `browser_*` names and to the two folds. Nothing else moved: the 36-method wire protocol did not change a byte, no permission was added, `import { TOOLS }` in your own fork reads `browser_*`. The release was dispatched as 1.7.0 and shipped as **1.7.1** because `site/package-lock.json` carries `es-module-lexer@1.7.0` and the version-map gate refuses to rewrite a lockfile it cannot move — mechanics, not a change of plan. The npm package is `kemudi` with the `navego-mcp` alias (unchanged by the owner's cancellation of the Kemudi site rebrand — this release does not unrename the package someone installed yesterday either), the extension's face stays the Kemudi one, and the CRX is not published with this release. The site is deployed from the merged main, claims 40 tools, and the live docs match it.
