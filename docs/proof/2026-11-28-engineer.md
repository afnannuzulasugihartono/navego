## What the shipped rule still got wrong, and what the owner lane did about it

The ticket's first bullet asks for liveness from the session's own heartbeat (`time.updated`)
**and** the absence of a running process, not from `outcome` alone. The rule in `cd17a6e2`
used the heartbeat, but it still let the stored `outcome` decide the idle case: a session that
never ran a turn was a target at any age, and a session that finished its last run stopped
being a target thirty minutes later, even while the OpenCode service that owns it was
running and the context was still resumable.

Measured with the shipped resolver and the live session record:

```text
live record: {"id":"ses_df1a6877cffen04QvCBE2T0ysR","title":"slot-console/agent-manager-20261126","outcome":"succeeded","ageMinutes":16}
resolved at the live heartbeat: ses_df1a6877cffen04QvCBE2T0ysR
same session, 40 minutes after its last run: null
same session, 40 minutes old, but never ran a turn: ses_df1a6877cffen04QvCBE2T0ysR
```

The operator lane read that in the round-2 report and closed both gaps itself in pull request
#518, merged as `bb43163` at 2026-11-27T21:17:18Z:

- `resolveSessionId` now takes the process table (`now`, `staleMs`, `processLines`) and
  `sendMessage` passes it from `readEvidence`, so the CLI uses it too: a fresh heartbeat is
  live; a stale heartbeat is live only while a process carries the session's title; otherwise
  the session is refused. Two new tests pin both cases, 9/9 pass.
- The register now names `tests/tooling/agent-fleet-message.test.ts` for the operator lane and
  the agent files were regenerated (`npm run roles:check`: 13 files match).

With the new register the scope gate that refused that path is green:

```text
$ npm run scope:role -- operator --base 114faf20 --head bb43163
the named roles may change all 8 paths
EXIT=0
```

One measurement is still open, and it is in the same file. The console target is addressed by
the roster title `slot-console`, and no process line carries it - the app runs as
`opencode.exe serve --service`, with no session title - so the process escape can never fire
for the operator console session, which carries `outcome: succeeded` after every completed
turn. On 2026-11-27 the console session's last message before a gap was at 19:47:42Z and its
next activity was at 21:00Z, so for about 43 minutes of that gap every report to the operator
was refused with `TARGET_SESSION_MISSING`. The round-3 report asks the owner lane to let the
console target stay addressable while the service that owns it runs, and to keep refusing a
finished lane worker whose worker process is gone.
