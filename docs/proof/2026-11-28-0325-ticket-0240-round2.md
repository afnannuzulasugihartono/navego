# Review verdict and fixes — ticket 0240 round 2

Report reviewed: round 2 named two real gaps that round 1 had not closed. Both are fixed here with tests written first.

## Gap 1: idle session with no outcome

Round 1's resolver used `!outcome || fresh heartbeat`. A session with no outcome but a stale heartbeat was still treated as live, so a report at 40 minutes old could be posted into a dead context. The new rule is:

- fresh heartbeat → live;
- stale heartbeat plus a running process for a session without an outcome → live;
- otherwise → refused.

Tests pinned the failure first:

```text
an idle session with no outcome is refused at the same age
a running process keeps a stale session addressable while it has no outcome
```

`resolveSessionId` now accepts optional `now`, `staleMs` and `processLines`; `sendMessage` passes the process table from `readEvidence`, so the CLI uses it too. 9/9 tests in `tests/tooling/agent-fleet-message.test.ts` pass.

## Gap 2: the test file belonged to no role

`npm run scope:role -- operator --base origin/main --head cd17a6e2` failed because `tests/tooling/agent-fleet-message.test.ts` was not named in any role's `scopePaths`. The operator register now names it; agent files were regenerated and `npm run roles:check` reports 13 matching files.
